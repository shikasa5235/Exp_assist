# 適正露出アシスタント — 実装指示書

Claude Code 向け。**この文書だけで最後まで実装できるよう、判断が必要な点はすべて確定済み。**
質問せずに通しで実装してよい。仕様の矛盾を見つけた場合のみ確認すること。

---

## 1. 何を作るか

撮影現場で「今の光でどう設定すればいいか」を出すツール。単なる露出計算機ではなく、
**撮影意図（ボカしたい／止めたい／日中シンクロ／スローシンクロ）から設定を逆算し、トレードオフを警告する**ところが価値。

ストロボ（日中シンクロ・スローシンクロ）は主要機能であり、おまけではない。

- 完全クライアントサイド。サーバー・DB・外部 API・CDN なし
- オフライン動作必須（電波の無い場所で使う）
- iPhone Safari での使用がメインターゲット
- UI 言語は日本語
- センサーはフルサイズ固定（換算計算は不要）

### 想定機材（初期値をこれに合わせる）

- ストロボ：**100Ws / 200Ws のバッテリーストロボ 2灯**（プロファイルとして登録し、切り替えて使う）
- ND：**ND2 / ND4 / ND8 / ND16**（1〜4段、重ね掛けで最大10段）

## 2. 配布形態と技術制約

**GitHub Pages にホストし、PWA として「ホーム画面に追加」して使う。**

| 制約 | 理由 |
| --- | --- |
| ビルドステップなし | 素の HTML/CSS/JS のみ。npm もバンドラも使わない |
| 外部リソース参照ゼロ | CDN・Web フォント・画像 API 一切禁止。オフラインで死ぬ |
| すべて相対パス | GitHub Pages のプロジェクトサイトは `/<repo>/` 配下。絶対パス `/` は 404 になる |
| ES Modules 使用可 | HTTPS 配信なので `<script type="module">` が使える |
| Service Worker はルート直下 | `sw.js` を `index.html` と同階層に置き、`register('./sw.js', { scope: './' })` で登録 |
| `manifest.webmanifest` の `start_url` は `"./"` | 同上の理由。`scope` も `"./"` |

### iOS Safari 固有の対応

- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`
- `<meta name="mobile-web-app-capable" content="yes">` と `apple-mobile-web-app-capable` の両方
- `apple-touch-icon.png`（180×180）を `<link rel="apple-touch-icon">` で指定
- セーフエリア対応：`padding: env(safe-area-inset-*)` をヘッダー・フッターに適用
- **input / select の `font-size` は 16px 以上**（下回るとフォーカス時に画面が勝手にズームする）
- `overscroll-behavior: none` でバウンスを抑制

## 4. アンビエント露出モデル（`exposure.js`）

### 4.1 基本式

- `N` = F値、`t` = シャッター速度（秒）、`S` = ISO 感度
- `EV_setting = log₂(N² / t)` … カメラ側の設定が表す露出値
- `EV_scene` = ISO 100 基準のシーン輝度（EV100）
- `comp` = 露出補正（段、正で明るく）
- `nd` = 装着中の ND による減光段数

**適正条件：**

```
EV_target = EV_scene + log₂(S / 100) − comp − nd
```

### 4.2 ソルバー（3つのうち2つが既知）

```js
t = N ** 2 / 2 ** EV_target
N = Math.sqrt(t * 2 ** EV_target)
S = 100 * (N ** 2 / t) / 2 ** (EV_scene - comp - nd)
```

計算はすべて連続値（float）で行い、**表示・確定の直前にだけ 1/3段へ丸める。** 途中で丸めると誤差が累積する。

## 5. ストロボ露出モデル（`flash.js`）

### 5.1 前提となる考え方

**アンビエント光とストロボ光は独立して制御される。ここがアプリの中核。**

| | 効く要素 | 効かない要素 |
| --- | --- | --- |
| アンビエント（背景） | F値・SS・ISO・ND | — |
| ストロボ（主被写体） | F値・ISO・距離・発光量・ND | **SS** |

ストロボの発光時間はシャッター速度より短いため、SS を変えてもストロボ露出は変わらない。
この非対称性が日中シンクロ／スローシンクロを成立させている。UI でもこの2系統を**必ず並べて表示**すること。

**ND はレンズ前に付くため、アンビエントとストロボの両方を等しく減光する。** ここを間違えないこと。

### 5.2 Ws から GN の推定と校正

**Ws（ワット秒）は蓄積エネルギーであって光量ではない。** 実際の GN はリフレクター・モディファイア・
発光管の効率で大きく変わり、メーカー公称値も測定条件がバラバラで信用できない。
そのため**推定値を初期値として持ち、テスト撮影1回で校正できる**設計にする。

**推定式：**

```
GN_base = k * Math.sqrt(Ws)      // k = 機材係数。既定 4.0、範囲 2.5〜5.0
```

Ws は電力なので光量に比例し、GN は光量の平方根に比例する。したがって Ws が倍なら GN は √2 倍（＝1段）。

| 出力 | 推定 GN（k=4.0） |
| --- | --- |
| 100Ws | 40 |
| 200Ws | 57 |

**校正機能（必須実装）：**

設定タブに「テスト撮影で校正」を置く。
入力：`ストロボから被写体までの距離(m)` / `適正だったF値` / `そのときの ISO` / `そのときの発光量`
から実測 GN を逆算し、`k` を更新する。

```
GN_measured = N * distance
GN_at_iso100_full = GN_measured / Math.sqrt(S / 100) * 2 ** (powerStops / 2)
k = GN_at_iso100_full / Math.sqrt(Ws)
```

校正値はストロボプロファイルごと・モディファイアごとに保存する。
未校正のプロファイルには UI 上に「推定値（未校正）」バッジを表示すること。

**モディファイア減光（§7.7 の表）：**

```
GN_mod = GN_base * 2 ** (-modifierLoss / 2)
```

### 5.3 有効 GN と距離

```
GN_iso = GN_mod * Math.sqrt(S / 100)
GN_eff = GN_iso * 2 ** (-(powerStops + ndStops + hssLossStops) / 2)

到達距離 = GN_eff / N
必要F値  = GN_eff / distance
```

**`distance` は「ストロボから被写体まで」であってカメラからではない。** オフカメラ運用が前提なので、
UI のラベルを必ず「ストロボ→被写体の距離」とすること。

**必要発光量の逆算：**

```
overStops = 2 * Math.log2(GN_iso_after_nd_hss / (N * distance))   // 正なら光が強すぎる
```

`overStops` をプロファイルの発光量レンジ内の整数段に丸めて発光量とし、
**丸めた端数は FEC（フラッシュ露出補正）として別に表示する。**
例：6.2段オーバー → 発光量 1/64 ＋ FEC −0.2段。

`overStops < 0` は光量不足。「◯段足りない」と出し、**距離を詰める／ISO を上げる／F を開ける／ND を外す**の4案を段数付きで提示する。

### 5.4 同調速度と HSS

- **同調速度**（既定 1/250、設定で変更可）より速い SS では通常発光が使えない。幕が写り込んで黒帯が出る
- 超えたい場合は **HSS（ハイスピードシンクロ／FP発光）**。ただし光量が大きく落ちる
- **HSS 対応可否はストロボプロファイルごとの設定項目**とする（非対応機では HSS 経路を出さない）

**HSS 損失モデル（近似）：**

```
hssLossStops = hssBaseLoss + Math.log2(tSync / t)     // t < tSync のとき
```

`hssBaseLoss` は既定 **2.0段**、設定で 1.0〜2.5 の範囲で調整可。

> UI に注記を出すこと：「HSS の光量低下は機種によって差があります。実測に合わせて設定タブで調整してください。」

### 5.5 閃光時間（スローシンクロで重要）

**発光量が大きいほど閃光時間は長くなる。** フル発光の 200Ws は閃光時間が 1/250 秒程度あり、
これでは動く被写体を止められない。スローシンクロで「背景は流して主被写体は止める」を狙う場合、
**止めているのは SS ではなく閃光時間**なので、ここを判定する必要がある。

§7.7 の表から発光量に対応する閃光時間を引き、§7.2 の必要 SS と比較して警告を出す。

### 5.6 ND 経路と HSS 経路の比較（日中シンクロの核心）

明るい屋外で絞りを開けたいとき、同調速度の壁を越える方法は2つある。**両方を計算して並べること。**

| 経路 | ストロボ側の損失 |
| --- | --- |
| ND を入れて SS を同調速度に留める | ND の段数ぶん（例：4段） |
| HSS で SS を上げる | `hssBaseLoss + 超過段数`（例：2 + 4 = 6段） |

**4段の場合、ND 経路のほうが2段ぶん明るく、到達距離は2倍になる。** ただし ND は SS が同調速度に固定される
（速い動きをアンビエントで止められない）、物理的な着脱が要る、という欠点がある。

両経路の**到達距離と必要発光量を並べて提示し、ユーザーに選ばせる。** どちらかを自動で選ばない。

### 5.7 先幕／後幕シンクロ

計算には影響しない。**SS が 1/60 より遅い場合は後幕シンクロを推奨する助言**を出す。
先幕だと動く被写体の残像が進行方向の前に伸びて不自然になるため。

## 6. ND の組み合わせ探索（`filters.js`）

所有 ND は設定で管理する（既定：ND2=1段 / ND4=2段 / ND8=3段 / ND16=4段、すべて所有）。

```
solveND(ownedStops, required) -> { totalStops, filters[], excess } | null
```

**アルゴリズム：** 所有 ND の全部分集合を列挙し、合計段数が `required` 以上のものを抽出。
`枚数の少ない順 → 超過段数の小さい順 → 合計段数の小さい順` でソートし先頭を返す。該当なしは `null`。

**枚数を最優先するのは、ガラスを重ねるほどケラレ・色被り・フレアが増えるため。**

既定セットでの結果（参考。ハードコードせず探索で求めること）：

| 必要段数 | 解 | 枚数 |
| --- | --- | --- |
| 1 | ND2 | 1 |
| 2 | ND4 | 1 |
| 3 | ND8 | 1 |
| 4 | ND16 | 1 |
| 5 | ND2 + ND16 | 2 |
| 6 | ND4 + ND16 | 2 |
| 7 | ND8 + ND16 | 2 |
| 8 | ND2 + ND8 + ND16 | 3 |
| 9 | ND4 + ND8 + ND16 | 3 |
| 10 | 全部 | 4 |
| 11 以上 | 解なし → 「所有NDでは最大10段まで」 |

3枚以上の解を返すときは `warn` レベルで「ケラレ・色被りに注意」を添える。

| 意図 | 優先ロジック |
| --- | --- |
| 背景をぼかす | F を開放に固定 → SS 算出 → 手ブレ限界を割ったら ISO を上げる |
| 動きを止める | 被写体を選ばせ §7.2 の SS に固定 → F 開放から → 不足分を ISO |
| 風景をくっきり | F8 固定・ISO ベース → SS 算出 → 三脚要否を判定 |
| 夜・手持ち | SS = 手ブレ限界に固定 → F 開放 → ISO 算出 |
| **日中シンクロ** | §8.1 |
| **スローシンクロ** | §8.2 |

5. **結果表示** — §8.3
6. **警告** — §9

**ストロボパネル共通の入力：** 使用プロファイル（100Ws / 200Ws から選択）/ モディファイア /
ストロボ→被写体の距離(m) / アンビエント目標段数

### 8.1 日中シンクロのロジック

明るい屋外で、背景を飛ばさずに逆光・影の被写体をストロボで起こす用途。

アンビエント目標段数の既定は **−1段**（範囲 −3〜+1）。

**算出手順：**

1. `EV_ambient_target = EV_target − アンビエント目標段数の絶対値` ※−1段なら背景が1段暗く写る
2. SS を同調速度に固定、ISO をベース感度に固定し、F値を算出（ND なし）
3. 算出 F値がユーザーの希望F値（既定：レンズ開放）より暗い場合、その差が **同調速度の壁への超過段数**
4. 超過段数がゼロなら通常発光で完結。ストロボ側を §5.3 で計算して終了
5. 超過段数が正なら **2経路を計算して並べる**（§5.6）
   - **ND 経路**：`solveND()` で必要段数をカバーする組み合わせを求め、その ND 段数を損失として到達距離と発光量を算出
   - **HSS 経路**：プロファイルが HSS 対応なら、希望F値でアンビエント適正になる SS を求め、`hssLossStops` を算出して到達距離と発光量を出す
6. どちらも成立しない場合は、F を絞る案を段数付きで提示する

**画面最上部に「同調速度の壁：◯段オーバー」を大きく出す。** この意図での最重要出力。

**比較表の形：**

```
              SS        ND      発光量    到達距離
ND経路      1/250     ND16      1/2       5.0m
HSS経路     1/4000    なし      1/1       2.5m   ← 2段不利
```

### 8.2 スローシンクロのロジック

暗所で、背景の夜景・アンビエントを SS で拾いつつ、主被写体をストロボで止める用途。

追加入力：三脚使用の有無 / 先幕・後幕。アンビエント目標段数の既定は **−1段**（範囲 −3〜0）。

**算出手順：**

1. F値を開放から、ISO をベースから開始
2. `EV_ambient_target` からアンビエント側の SS を算出
3. 三脚なし → 手ブレ限界と比較。割っていたら ISO を上げて SS を稼ぎ、それでも足りなければ警告
4. 三脚あり → 手ブレ判定をスキップし、SS 制限を 30″ まで開放
5. ストロボ側：F値・ISO・距離から必要発光量と FEC を算出
6. **閃光時間の判定（§5.5）：** 算出した発光量に対応する閃光時間を §7.6 から引き、
   被写体の必要 SS より遅ければ「主被写体が止まりません」と警告する
7. SS が 1/60 より遅ければ「後幕シンクロ推奨」＋ゴースト注意を出す

### 8.3 結果表示のレイアウト

## 9. 警告ロジック（`advisor.js`）

`{ level: 'info' | 'warn' | 'alert', message }` の配列を返す。**必ず「何段足りない／超過している」を数値で示すこと。**

### アンビエント系

| 条件 | レベル | メッセージ例 |
| --- | --- | --- |
| SS < 手ブレ限界 | warn | 手ブレしやすい速度です（限界より◯段遅い）。三脚か、ISO を◯段上げてください |
| SS < 被写体ブレ基準 | warn | 被写体が流れます。1/◯以上にしてください |
| 必要 ISO > ISO上限 | alert | 光量が◯段足りません。開放を明るく、または三脚が必要です |
| 必要 F < 開放F値 | alert | このレンズでは◯段足りません |
| 必要 SS < 機種の最速 | alert | 明るすぎます。◯段の減光が必要です（ND◯） |
| F > 11 | info | 回折で解像が落ち始めます |
| ISO > 上限の 1/2 | info | ノイズが目立ち始める領域です |
| SS ≧ 1/2 秒 | info | 三脚推奨 |

### ストロボ系

| 条件 | レベル | メッセージ例 |
| --- | --- | --- |
| SS > 同調速度 かつ HSS 非対応 | alert | 同調速度（1/◯）を◯段超えています。このストロボは HSS 非対応です。ND◯を使ってください |
| SS > 同調速度 かつ HSS off | alert | 同調速度を◯段超えています。黒帯が出ます |
| HSS 損失 > 4段 | warn | HSS で約◯段の光量ロス。到達距離は◯m まで落ちます |
| ND 装着でストロボ到達距離が半減以上 | warn | ND◯段でストロボも◯段減光されます。到達◯m |
| 必要発光量 < 最小発光量 | warn | 光が強すぎます。距離を◯m 離すか、ISO を◯段下げてください |
| 必要発光量 > 1/1 | alert | ストロボが◯段足りません。距離を◯m まで詰める／ISO を◯段上げる／F を◯段開ける／ND を外す |
| 到達距離 < 設定距離 | alert | 光が届きません（到達◯m／設定◯m） |
| 閃光時間 > 被写体の必要SS | warn | 発光量◯では閃光時間 1/◯。この被写体は止まりません。発光量を◯段下げて距離を詰めてください |
| ND 3枚以上 | warn | ND を◯枚重ねます。ケラレ・色被りに注意してください |
| スローシンクロで SS < 1/60 | info | 後幕シンクロ推奨。被写体が動くと残像が出ます |
| 発光量 ≧ 1/2 | info | フル発光に近く、連写ではチャージが追いつきません |
| プロファイルが未校正 | info | GN は Ws からの推定値です。テスト撮影で校正すると精度が上がります |

警告なしの場合は `{ level: 'info', message: 'この設定で撮れます' }` を1件返す。

## 10. 確定した表示ルール

### 10.1 代替案の選び方（主案＋2案）

3案は**すべて同じ `EV_target` 上の等価組み合わせ**であることを保証する。主案を中庸に置き、
**「ノイズ か ブレ か」というトレードオフの両端**を代替案として提示する。

| 案 | 選び方 |
| --- | --- |
| 主案 | §8 の意図別ロジックの結果 |
| 代替A「ブレを避ける」 | 手ブレ・被写体ブレの警告が消えるまで SS を上げ、その分を ISO で補う。ISO 上限まで |
| 代替B「画質を優先」 | ISO を主案より最低1段下げ、その分を SS の低速化（または F を開ける）で補う |

代替案が主案と同一になる、または実用範囲外で成立しない場合は**その案を出さない**。無理に3案を埋めない。

**日中シンクロ時はこの3案ではなく、§8.1 の ND 経路 / HSS 経路の比較表に置き換える。**

### 10.2 等価露出一覧

- **並び順：F値の昇順**（開放側 → 絞り側）
- **刻み：F値 1段刻み**（1/3段刻みだと行数が多すぎて現場で読めない）
- **実用範囲：** F は設定の開放F値〜F16、SS は設定の SS 上限〜30″、ISO は設定の下限〜上限
- 上記をすべて満たす行のみ生成。**最大9行**、超える場合は主案の行を中心に前後を切る
- 各行に警告アイコン（手ブレ／回折／高感度）を小さく添える
- 主案に該当する行はハイライトする

### 10.3 EV ルーラーの表示レンジ

- **±3段（1/3刻みで19目盛）を既定とする**
- 理由：実機の露出補正ダイヤルが ±3段主流で体感が合う。±5段にすると1段あたりの物理幅が狭まり屋外での視認性が落ちる
- ±3段を超えるズレは針を端に固定し、`+3.0 ↑` のように数値でクリップ表示する

## 11. デザイン方針

現場で片手・屋外・急いで見る道具。装飾より判読性。

### トークン（`:root` の CSS カスタムプロパティ）

ライトを基調とし、`prefers-color-scheme: dark` で切替。

```
ライト  --paper #EDEFF1 / --panel #FFFFFF / --ink #14181C / --muted #5C666F / --rule #C3CAD1
ダーク  --paper #0F1418 / --panel #171E24 / --ink #E8EDF1 / --muted #93A0AB / --rule #2B353D
共通    --ok #1F6F5C / --warn #8A5A00 / --alert #A32020 / --flash #2D5FA8
```

`--flash` はストロボ系統の識別色。アンビエント系統との視覚的な分離にのみ使い、装飾に使わない。

### タイポグラフィ

Web フォント禁止（オフライン要件）のため、システムフォントを役割で使い分ける。

- 数値：`ui-monospace, SFMono-Regular, "SF Mono", Menlo, monospace` ＋ `font-variant-numeric: tabular-nums`
- 本文：`-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Noto Sans JP", sans-serif`
- 主役の数値はサイズとウェイトで作る。F値・SS・ISO の結果は 40px 以上、ラベルは 12px

### シグネチャ要素：EV ルーラー

画面中央に**横向きの段数目盛り**。1/3段刻み、1段ごとに長い罫。中央が適正で、現在の設定が何段ズレているかを針が指す。

その直下に **F / SS / ISO の3本の平行トラック**を並べる。1つを動かすと他が連動して滑り、
「絞ると SS が遅くなる」という相互関係が目で見てわかる。

**ストロボ ON のときは4本目のトラック（発光量）を追加する。** ただしこのトラックは SS の動きに連動しない
——SS を動かしても発光量トラックが微動だにしないことが、「ストロボは SS に影響されない」という原理そのものを見せる。
**一方 ND を足すと、4本すべてが同時に動く**（ND は両系統に等しく効くため）。
この2つの挙動の対比がアプリの一番の見どころなので、実装コストを寄せてよい。他の画面要素は徹底して静かに作ること。

### モーション

トラックの連動スライド（150ms / ease-out）のみ。それ以外にアニメーションを足さない。
`prefers-reduced-motion: reduce` では即時切り替え。

### 品質の下限

- タップ領域は 44×44px 以上
- キーボードフォーカスリングを消さない
- 警告は色だけでなくアイコンと文言でも区別する
- 320px 幅まで崩れない

## 14. 実装ルール

- 同じ処理を書きそうになったら関数に切り出す。冗長な分岐は表引きに置き換える
- マジックナンバーを直書きしない。定数は `scenes.js` か各モジュール冒頭にまとめる
- ロジックと DOM を混ぜない。`ui.js` から計算モジュールを呼ぶ一方向のみ
- 関数には JSDoc で引数と戻り値の型を書く
- `storage.js` は `try/catch` で必ず包む（プライベートブラウズ等で例外を投げる環境がある）。失敗時は既定値で続行し、機能は落とさない
- **近似モデル（Ws→GN・HSS 損失・モディファイア減光・閃光時間・シーン EV）を使う箇所は、UI に「目安である」旨と調整手段を必ず併記する。** 断定的な数値を出すと現場で外れる
