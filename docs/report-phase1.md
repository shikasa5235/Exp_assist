## 2. L9 が「スナップしたら落ちる」形になっているか

### 仕組み

L9 は3つを同時に判定する。

| # | 判定 | 何を守るか |
| --- | --- | --- |
| ① | `parsed.exposureTime === 1/4405` かつ `parsed.fNumber` が `1.7799999713880652` と 1e-12 以内 | **`exif.js` が有理数をそのまま返している** |
| ② | 合成 JPEG 経由の EV と、リテラルを直接渡した EV が 1e-12 以内で一致 | **どちらの層でも寄せていない** |
| ③ | `Math.abs(ev − snappedEv) > 0.05` かつ `ev ≈ 14.0905` | **寄せた実装と判別できている** |

`snappedEv` はテスト内で `snap(F/SS/ISO, …)` を使ってその場で計算する。ハードコードしていないので、
系列テーブルが変わっても比較対象が自動的に追従する。

```
実測値のまま  F1.7799999713880652 / 1/4405   / ISO80    → EV 14.0905
グリッドへ寄せ F1.7818（idx 5）   / 1/4096(2^-12) / ISO79.37(idx 2) → EV 14.0000
差 0.0905段
```

判定の許容は 0.002段。差 0.0905段はその 45倍あるので、**寄せた実装は必ず落ちる。**

### 実際に壊して確かめた

| 変異 | 落ちたテスト |
| --- | --- |
| `exif.js` が `snap()` で寄せる | E1・E3・E4・**L9** |
| `lightmeter.js` が入力を `snap()` で寄せる | L1・L2・L3・**L9** |

**最初の版では変異A（`exif.js` 側）で L9 が落ちなかった。** リテラルを直接渡していて
パーサを通っていなかったため。合成 JPEG を通す①②を足して両方の層を守る形にした。

## 3. ほかの変異テスト

| 変異 | 落ちたテスト | 判定 |
| --- | --- | --- |
| `lightmeter` が `exposureBias` を EV に足さない | L10 | 意図どおり |
| `exif.js` が `ExposureBiasValue` を読まない | E10 | 意図どおり |
| `exif.js` が GPS を読んで返り値に載せる | E7 | 意図どおり |
| `compute` の `measuredScene` を常に false | I1 | 意図どおり |
| `SCENES` に `measured`（contrast 2.5）を足す | I3 | 意図どおり |

**予測が外れたもの（テストは正しい）**

- 変異「bias を EV に足さない」で **L11 は落ちなかった。** L11 は `measurementNotes` の文言を
  見ており、EV には依存しない。役割分担として正しい（L10 が EV、L11 が注記）。
- 変異「`measuredScene` を false」で **I3 は落ちなかった。** I3 は白飛び警告の有無を見ており、
  実際の仕組みは「`'measured'` が `SCENES` に無いので表引きが外れる」ほう。フラグではなく
  仕組みを見ているので、こちらのほうが強い。別の変異（`SCENES` に足す）で落ちることを確認した。
