# 適正露出アシスタント — UI/UX 仕様書

`exposure-app-spec.md`（計算仕様）と対になる文書。**Claude Code は両方を読むこと。**
計算ロジックは向こう、見た目と操作はこちら。矛盾した場合は計算仕様を優先する。

---

## 1. 設計の前提

**利用文脈：** 屋外、片手操作、急いでいる、直射日光下または暗所、手袋の可能性あり。

ここから設計原則が3つ導かれる。すべての判断はこれに従う。

| 原則 | 意味 |
| --- | --- |
| **1. キーボードを出さない** | ソフトキーボードは画面の半分を潰し、片手では打てない。9割の操作をタップとスワイプで完結させる |
| **2. 結果は常に見えている** | 入力をいじりながら結果が変わるのを見たい。結果パネルは画面下部に固定し、スクロールで消えない |
| **3. 入力を拒否しない** | 範囲外の値は弾かずクランプして通知する。現場で「入力が通らない」のが最悪の体験 |

これらに反する実装は、他がどれだけ整っていても不採用とする。

## 2. 画面骨格

**モバイル1カラム（〜767px）が基準。** 固定ヘッダー／スクロール領域／固定結果パネルの3層。

```
┌──────────────────────────────────────┐
│ かんたん │ 計算 │ 設定        EV 15.0 │ ← sticky header 52px + safe-area-top
├──────────────────────────────────────┤
│                                      │
│  シーン                               │
│  ┌─────┬─────┬─────┬─────┐          │
│  │ 快晴 │ 薄曇 │ 曇り │ 日陰 │  →     │  横スクロールタイル
│  └─────┴─────┴─────┴─────┘          │
│  微調整   −2 ──────●────── +2   0.0段 │
│                                      │
│  意図                                 │
│  ┌────────┬────────┬────────┐       │
│  │ ぼかす  │ 止める  │日中シンクロ│  →   │
│  └────────┴────────┴────────┘       │
│                                      │
│  ストロボ                             │
│  200Ws ▾        標準リフレクター ▾    │
│  距離   1  1.5  [2]  3   5   8   m   │  チップ
│  背景   −3  −2  [−1]  0  +1     段   │
│                                      │  ← scroll body
├──────────────────────────────────────┤
│  同調速度の壁            ＋4.0 段     │ ← sticky result 240px
│  ┌──────────────┬──────────────────┐│
│  │ アンビエント   │ ストロボ          ││
│  │ F2.8          │ 1/2   FEC −0.1   ││
│  │ 1/250         │ 到達 5.0m        ││
│  │ ISO100  ND16  │ 閃光 1/400       ││
│  └──────────────┴──────────────────┘│
│  ND経路 5.0m  ／  HSS経路 2.5m        │
│  ⚠ ND16 でストロボも4段減光します      │
└──────────────────────────────────────┘
                            + safe-area-bottom
```

**高さ配分：** ヘッダー 52px 固定。結果パネルはストロボOFFで 168px、ONで 240px。
残りがスクロール領域。結果パネルの高さが変わるときは 200ms でトランジションし、
スクロール領域に `padding-bottom` を同期させて内容が隠れないようにする。

### 2.1 結果パネルの高さ（ユーザーが3段階で選ぶ）

屋外・片手という条件では、**入力と結果のどちらに画面を配分するかは撮影者が決める**。
`state.ui.panelSize` の3状態を持ち、`setState` 経由でのみ変更する。**storage に永続化**し、
次回起動時に前回の状態を復元する（現場で好みが決まったら固定されるため）。

| 値 | 高さ | 見えるもの |
| --- | --- | --- |
| `'expanded'` | 画面高の **70%**（`70dvh`） | EV ルーラーとトラックを大きく見る |
| `'normal'`（既定） | `46dvh`（240px 相当／ストロボOFFで168px） | 現状のすべて |
| `'minimal'` | **72px ＋ safe-area**（下限。中身を隠して自然な高さ） | **主案の数値1行のみ** |

**高さの単位は `dvh`（動的ビューポート）を使う。`vh` は使わない。**
iOS Safari の `100vh` / `height: 100%` は**アドレスバーが隠れた状態の高さ**を返すため、
下端の固定要素がアドレスバーに潜って見切れる。`html, body { height: 100dvh }` で追従させ、
`vh` はフォールバックとして前段に残す。

**アドレスバーは `env(safe-area-inset-bottom)` に含まれない。** ホームバーとは別要素なので、
safe-area はパネルの `padding-bottom` で、アドレスバーは `dvh` で、それぞれ別に吸収する。

**`minimal` は px でクリップしない。** `max-height: 56px` のような固定値で切ると数値が見切れる。
他の要素を `display: none` で隠し、`min-height: calc(72px + safe-area)` で下限だけ確保する。

`expanded` が 70% なら入力領域は 30% 残る（16 Pro Max 縦持ち 956pt で約287pt ＝
ヘッダーとタブと1〜2項目が見える）。結果を追い込むための状態なのでこれで足りる。

**`minimal` で残すもの：** `F2.8 ・ 1/250 ・ ISO200`（ストロボONなら `・ 発光 1/8` を追加）。
EV ルーラー・トラック・警告文・経路比較は隠す。**警告が出ている場合は行末にアイコンだけ残す**
（何かあることが分かるように）。

> **設計原則2「結果は常に見えている」との関係：** `minimal` でも核心の数値は見えているので原則を満たす。
> **完全に隠す状態は作らない。**

**操作：** 結果パネルの上端にハンドル（横棒のグリップ）を置く。掴む場所が見えることで発見しやすくなる。

| 操作 | 動作 |
| --- | --- |
| ハンドル上で上スワイプ | 1段階 `expanded` 方向へ |
| ハンドル上で下スワイプ | 1段階 `minimal` 方向へ |
| ハンドルのタップ | `normal` に戻す |
| ハンドル上で ↑/↓ キー | 1段階ずつ移動 |

- **ハンドル以外（パネル内部）では反応させない。** 等価露出一覧のスクロールと衝突する
- ハンドルのタップ領域は 44px 以上。視覚的な横棒は 32×4px で、上下に余白を取って領域を確保する
- **連続追従はしない。** 閾値（40px）を超えた時点で隣の状態へ吸着させる。実装も操作も単純になる
- アニメーションは 200ms ease-out。`prefers-reduced-motion` では即時
- **高さ 600px 未満の画面では `expanded` を選べない**（画面高の60%が入力領域を潰すため）。
  その場合は `normal` と `minimal` の2状態。クランプ規則は `state.js` の純粋関数
  `clampPanelSize(size, viewportHeight)` に置き、描画・保存・テストで同じ規則を使う
- **`panelSize` はタブをまたいで維持する。** かんたんタブで `minimal` にしたら計算タブでも `minimal`。
  設定タブには結果パネルが無いので表示されない（現状どおり）

**EV ルーラーの置き場所：** 結果パネルの最上部、見出し行の直下に横幅いっぱいで置く。
ストロボOFF時はここに3本トラック、ON時は4本トラック（計算仕様 §11 参照）。

**ただし計算タブでは F/SS/ISO のトラックを出さない**（本体側の操作ホイールと重複するため）。
計算タブはストロボOFFでトラックなし、ONで発光量のみ1本。本数の決定表は計算仕様 §11 にある。

## 3. 入力コントロールの選定

**原則1（キーボードを出さない）を満たすための、コントロール種別の確定表。**

| 入力項目 | コントロール | 選定理由 |
| --- | --- | --- |
| シーン | 横スクロールタイル（アイコン＋ラベル、88×72px） | 15項目を2タップ以内。ドロップダウンは選択中に中身が見えない |
| シーン微調整 | 横スライダー（1/3段スナップ、±2段） | 連続量なのでスライダーが自然。目盛りに吸着させる |
| 意図 | 横スクロールチップ（6項目） | 排他選択。セグメントだと6個は狭すぎる |
| 焦点距離 | プリセットチップ `24 / 35 / 50 / 85 / 135 / 200` ＋「その他」 | 実際に使う値は数個。「その他」だけ数値入力に落とす |
| ストロボ距離 | プリセットチップ `1 / 1.5 / 2 / 3 / 5 / 8 m` ＋「その他」 | 同上 |
| アンビエント目標段数 | チップ `−3 / −2 / −1 / 0 / +1` | 離散5値。スライダーは精度過剰 |
| 被写体（動き） | 横スクロールチップ（6項目） | §7.2 の6分類そのまま |
| ストロボ選択 | ドロップダウン（2〜数件） | 件数が少なく、切替頻度も低い |
| モディファイア | ドロップダウン（9件） | 一覧性より省スペースを優先。変更頻度が低い |
| ND | トグルチップ `ND2 / ND4 / ND8 / ND16`（複数選択） | 所有フィルタを直接タップ。合計段数を右に表示 |
| F / SS / ISO（計算タブ） | **横ホイールピッカー**（1/3段目盛り、スワイプ） | EV ルーラーのトラックと同一コンポーネント。実機のダイヤル感覚に一致 |
| ロック（計算タブ） | 各トラック左端の鍵アイコン（トグル） | 2つロックで3つ目が自動算出（計算仕様 §8） |
| 三脚 / 先幕後幕 / HSS | トグルスイッチ | 2値 |
| 逆光（空が明るい） | トグルスイッチ | 2値。**白飛び判定にだけ効き、露出計算そのものは変えない**。ストロボパネル内に置き、日中シンクロ・スローシンクロの両方で出す。逆光かどうかはシーンEV では区別できない（同じ EV で順光にも逆光にもなる）ため、シーンのタイルに列を増やさずトグル1つで表す。計算仕様 §9.1 |
| 数値入力（「その他」と設定タブ） | `<input type="text" inputmode="decimal">` | `type="number"` はスピナーが出て iOS で扱いにくい。`inputmode` でテンキーだけ出す |

**すべての数値入力は `font-size: 16px` 以上。** 下回ると iOS がフォーカス時に自動ズームする。

### 横ホイールピッカーの挙動

- 幅いっぱい、高さ 56px。中央に固定の指針（縦線）
- 目盛りは 1/3段ごと。1段ごとに長い罫と数値ラベル
- スワイプでスクロール、指を離すと最寄りの 1/3段にスナップ（150ms ease-out）
- スナップ時に軽い触覚フィードバック（`navigator.vibrate?.(8)`、非対応環境は無視）
- 端に到達したらゴムバンドせず止める。到達を `--rule` の濃い線で示す
- **タップ領域は高さ 56px 全体**。目盛り自体は細くてよいが当たり判定は太く

#### 選べる範囲の制限（計算タブのみ）

設定した機材の限界を超える値をダイアルできてしまうと、存在しない設定を選べる。
**入力を拒否するのではなく、そもそも選べない形にして構造的に防ぐ**（微調整スライダーと同じ方式）。

**制限する軸としない軸を分ける。** 判断の基準は「物理的な限界か、好みか」。

| 軸 | 下限 | 上限 | 根拠 |
| --- | --- | --- | --- |
| F | `lens.fMin`（開放） | `lens.fMax`（最小絞り） | レンズに無い絞りは存在しない |
| SS | 30″（系列の最遅） | `camera.maxSS` | カメラに無いシャッター速度は存在しない |
| ISO | `isoFloorOf(state)` | **制限しない** | 下限は機材の限界。上限は好み（下記） |

**実用ISO上限（`camera.isoMax`）で上を止めないこと。** ノイズを許容して上げるのは
撮影者の判断であり、機材の限界ではない。止めると「粗くてもいいから写す」ができなくなる。
高感度警告が別に出るので情報は失われない。
**発光量の上限（`powerCeilingStops`）を fixed モードに適用して不具合になったのと同じ構造。**

**ISO の下限は制限してよい。** 拡張ISO トグルが同じ画面にあり1タップで外せるため、
「設定タブへ行かないと解除できない制限」にはならない。この条件が崩れたら制限も外すこと。

##### 見せ方

- **範囲外の目盛りは消さずグレーで残す**（`opacity: .35`）。どこが限界かが見えるほうが
  「なぜここで止まるのか」が分かる。消すと限界がホイールの端と区別できない
- 限界の位置に区切り線（`--rule` の縦線）。**外側に目盛りが残っている側だけ**に引く。
  系列の端（SS の 30″ など）は限界ではないので引かない
- 範囲外へドラッグしたらそこで止め、**トーストを一度だけ**出す。
  同じ限界に当たり続ける間は鳴らさない（範囲内へ戻ると解除）
- `aria-valuemin` / `aria-valuemax` は**操作できる範囲**を指す（系列の端ではない）
- キーボードの矢印もドラッグと同じ範囲・同じ通知規則

##### 読み取り専用トラック（結果パネル）は対象外

グレーアウトもしない。表示する値は既にクランプ済みで、範囲外を示す意味がない。
`wheel.js` は共有部品なので、**範囲を渡さなければ従来どおり系列いっぱいで動く**こと。

##### 制限値が変わったときの既存値

拡張ISO を ON→OFF、設定タブで開放F値を変更、といった操作で保存済みの値が範囲外になる。
**範囲内へクランプし、何をなぜ変えたかをトーストで伝える。黙って値を変えない。**
クランプは表示側ではなく `state` に対して行う（詳細は `docs/MAINTENANCE.md` §12.3）。

#### スクロールとの競合（実機で不具合が出た箇所）

**操作するホイールには `touch-action: pan-y` を宣言する。**

```css
.wheel:not(.is-readonly) { touch-action: pan-y; }
```

横方向のジェスチャはアプリが受け取り、縦方向はページのスクロールに渡す、という宣言。
ホイールは横操作なのでこれで競合が消える。

**`touch-action: none` にしないこと。** ホイール上から始めた縦スクロールができなくなり、
**画面の大部分がホイールで埋まっている計算タブでは操作不能になる。**

**読み取り専用トラック（結果パネル側）には付けない。** 入力を受け付けないので競合しない。
付けても害はないが、「ここは操作する要素」という意図を1行で表すために分ける。

**親のスクロールコンテナ（`.scroll-body`）には付けない。** 範囲を広げると
ページ全体のスクロールが壊れる。

#### 実機で起きた症状（記録）

横スワイプ中に縦スクロールが挟まるとダイヤルが大きく飛び、繰り返すと悪化した。
`touch-action` が無いためブラウザがタッチを引き取って `pointercancel` を発火し、
その `pointercancel` が**確定処理に繋がっていた**ため、ユーザーが選んでいない値が
commit されていた。飛んだ値が次のジェスチャの起点になるので悪化した。
PC で再現しなかったのは、マウスドラッグではスクロールと競合しないため。

#### 採らない案：停止時間による判定

**「1秒以上停止したらスクロールを許可する」という案は採らない。**

- 遅延が体感を悪くする（スクロールしたいときに1秒待たされる）
- 判定の条件が増えて別の不具合を生む
- `touch-action` は宣言1行でブラウザ側が処理する

## 4. カラートークン

**3テーマを構造的に許す設計にする**（ライト／ダーク／将来のナイトモード）。
`data-theme` 属性でルート要素を切り替え、CSS変数を上書きする方式。

```css
:root, [data-theme="light"] { ... }
[data-theme="dark"] { ... }
```

`prefers-color-scheme` を初期値とし、**ヘッダーに手動オーバーライド（自動／ライト／ダーク）を置く。**
夜の現場で OS がライトのままだと目が潰れるため、手動切替は必須。

### ライト（屋外・直射日光下での判読性を最優先）

| トークン | 値 | 用途 | 白地とのコントラスト |
| --- | --- | --- | --- |
| `--paper` | `#F4F6F8` | ページ背景 | — |
| `--panel` | `#FFFFFF` | パネル・カード | — |
| `--ink` | `#0E1216` | 主テキスト・数値 | 18:1 |
| `--ink-2` | `#4A5560` | 副テキスト・ラベル | 7.6:1 |
| `--rule` | `#C8D0D8` | 罫線・境界 | — |
| `--ok` | `#0F5D4A` | 適正・成功 | 7.3:1 |
| `--warn` | `#7A4C00` | 注意 | 7.1:1 |
| `--alert` | `#96131A` | 警告 | 7.6:1 |
| `--flash` | `#14448F` | ストロボ系統の識別 | 9.2:1 |

### ダーク（夜間撮影）

| トークン | 値 | 用途 | パネル地とのコントラスト |
| --- | --- | --- | --- |
| `--paper` | `#0B0F12` | ページ背景 | — |
| `--panel` | `#151B21` | パネル・カード | — |
| `--ink` | `#EAF0F5` | 主テキスト・数値 | 14:1 |

| `--rule` | `#2A343D` | 罫線・境界 | — |

### 使用規則

- **`--flash` はストロボ系統の識別にのみ使う。** 装飾・強調・CTA に流用しない
- 色だけで意味を伝えない。警告は必ず**アイコン＋文言**を伴う
- コンポーネント内に生の hex を書かない。すべてトークン経由
- **ダークはライトから推測せず、独立して実測すること**

## 5. タイポグラフィ

Web フォント禁止（オフライン要件）。システムフォントを役割で使い分ける。

```css
--font-num:  ui-monospace, SFMono-Regular, "SF Mono", Menlo, monospace;
--font-text: -apple-system, BlinkMacSystemFont, "Hiragino Sans", "Noto Sans JP", sans-serif;
```

**数値には必ず `font-variant-numeric: tabular-nums` を付ける。** 桁が揺れると読み違える。

| 役割 | サイズ / 太さ | 字間 | 用途 |
| --- | --- | --- | --- |
| `display` | 44 / 700 | −0.02em | 結果の主役数値（F値・SS・ISO） |
| `numeric-lg` | 28 / 600 | −0.01em | 段数オーバー表示、到達距離 |
| `numeric-md` | 20 / 600 | 0 | ストロボ側の数値、一覧の値 |
| `title` | 15 / 600 | 0 | パネル見出し |
| `body` | 15 / 400 | 0 | 本文・警告文 |
| `label` | 12 / 600 | 0.04em | 項目名（「シーン」「意図」など） |
| `caption` | 12 / 400 | 0 | 補足・単位・注記 |
| `input` | 16 / 400 | 0 | 入力欄（16px を下回らない） |

行高は本文 1.6、数値 1.1。**12px を下回るテキストを作らない。**

## 6. アイコン

外部ライブラリを読めない（オフライン・CDN 禁止）ため、**インライン SVG を自前で定義する。**
`index.html` の先頭に `<svg style="display:none">` の `<symbol>` 集合を置き、`<use>` で参照する。

**仕様：** viewBox `0 0 24 24` / `stroke="currentColor"` / `stroke-width="1.5"` /
`stroke-linecap="round"` / `fill="none"` / アウトライン統一。

**絵文字をアイコンとして使わない。** フォント依存で環境差が出るため。

必要な 16 種：

| キー | 用途 |
| --- | --- |
| `tab-easy` / `tab-calc` / `tab-settings` | タブ |
| `shake` | 手ブレ警告 |
| `motion` | 被写体ブレ警告 |
| `diffraction` | 回折 |
| `noise` | 高感度ノイズ |
| `flash` | ストロボ |
| `nd` | ND フィルタ |
| `hss` | ハイスピードシンクロ |
| `tripod` | 三脚推奨 |
| `lock` / `unlock` | 計算タブのロック |
| `info` / `warn` / `alert` | 警告レベル3種 |

アイコン単独のボタンには必ず `aria-label` を付ける。サイズは `--icon-sm: 16px` / `--icon-md: 24px` の2種のみ。

## 7. スペーシングと寸法

4px を基本単位とする。`4 / 8 / 12 / 16 / 24 / 32` 以外の値を使わない。

| トークン | 値 |
| --- | --- |
| `--r-panel` | 10px（パネル角丸） |
| `--r-chip` | 8px（チップ角丸） |
| `--r-pill` | 999px（トグル） |
| `--tap-min` | 44px（最小タップ領域） |
| `--gap-tap` | 8px（隣接タップ領域の最小間隔） |

- **すべてのタップ対象は 44×44px 以上。** 見た目が小さくても当たり判定を広げる
- 隣接するタップ対象の間隔は 8px 以上
- 押下フィードバックは 80〜150ms 以内に返す（背景色または不透明度。**レイアウトを動かさない**）
- 無効状態は `disabled` 属性を付け、不透明度を下げ、タップに反応させない

### 4px リズムの例外（手順11で分類・確定）

**「余白」には 4 の倍数のみを使う。** ただし以下は余白ではないか、半段にすることで
見た目が整っている箇所で、**意図的な例外として認める。**

| 種類 | 値 | 箇所 | 認める理由 |
| --- | --- | --- | --- |
| アイコンと文字の間隔 | `gap: 6px` | `.tab` / `.field-label` / `.chip` | SVG 自身の内側余白を含めた実効間隔が 8px 相当になる。8px にすると離れて見える |
| テキストブロックの行間隔 | `gap: 6px` | `.warnings` / `.setup-dots` | タップ対象ではない。警告は同時に最大5件出るのでパネル高さの予算に直接効く |
| タップ対象の左右パディング | `padding: 0 10px` / `0 14px` | `.tab` / `.chip` | 文字幅に合わせた値。高さ 44px は別途保証済み。4 の倍数に丸めると 320px 幅での折り返しが変わる |
| 数値表示の左右パディング | `padding: 8px 10px` | `.sys-card` / `.input` | 8px では等幅数字が窮屈、12px では2カラムで幅が足りない |
| 表のセル | `padding: 6px 8px` | `.path-compare` | 4行あるため上下 8px にすると表が 8px 高くなる（パネル予算） |
| ピル型の上下 | `padding: 2px 8px` | `.badge` | 11px の文字に 4px を足すと縦に膨らむ |
| 光学的なベースライン合わせ | `1px` / `2px` / `-2px` | `.warn-item .icon` / `.sys-sub` / `.slider-scale` / `.warn-action` | 余白ではなく位置の微調整 |
| 当たり判定の吸収 | `-6px` / `-10px` | `.panel-handle` / `.warn-help` / `.badge-link` | 44px を行高に膨らませないための計算値。見た目の余白ではない |
| 幾何計算 | `3px` / `13px` / `14px` / `26px` | `.toggle-knob` / `.ev-scale-tick` / `.ev-ruler` | つまみの中心・目盛りとラベルの絶対配置。要素寸法から決まる |
| セーフエリアとの合算 | `calc(10px + var(--sab))` | `.result-panel` | 実効値は端末依存でリズムに乗らない |

**上表に無い逸脱は「漂流」として直す。** 手順11では4件（`.header-right` と `.result-badges` の
タップ間隔 6px → `--gap-tap`、`.field-error` の 6px → 8px、`.toast` の上下 10px → 12px）を修正した。
`18px` のアイコンは `--icon-xs` トークンにした。

## 8. モーション

| 対象 | 時間 / イージング |
| --- | --- |
| トラックの連動スライド | 150ms / ease-out |
| ホイールのスナップ | 150ms / ease-out |
| 結果パネルの高さ変化 | 200ms / ease-out |
| タブ切替 | 120ms / ease-out（クロスフェードのみ、横スライドしない） |
| 押下フィードバック | 80ms |

**これ以外にアニメーションを足さない。** スクロール連動の演出、フェードイン、パララックスはすべて不要。

`@media (prefers-reduced-motion: reduce)` ではすべて `duration: 0` にする。
ただし**状態変化そのものは残す**（消すのは動きだけで、フィードバックは消さない）。

### アニメーションしてよいプロパティ

**連続的・スクロール駆動のアニメーションは `transform` と `opacity` に限る**（レイアウトとペイントを避ける）。

**離散操作による一度きりの遷移**では、ペイントのみのプロパティ
（`background-color` / `border-color` / `box-shadow`）を使ってよい。
押下フィードバックに背景色を使うのはこの範囲（上の表の「押下フィードバック」）。

**レイアウトを動かすプロパティ**（`height` / `max-height` / `width` / `margin` / `top` / `left`）は、
**実機で滞りがないことを確認した場合のみ。** 確認したら理由と代替案を
`docs/MAINTENANCE.md` §12 に記録する（現在の例外は結果パネルの3段階遷移の `max-height` 1件）。

## 9. 状態管理

フレームワーク無しなので、**単一ステート＋一方向レンダリング**を厳守する。
これを守らないと DOM に状態が散って必ず破綻する。

```
state ──▶ compute(state) ──▶ derived ──▶ render(state, derived) ──▶ DOM
  ▲                                                                  │
  └────────────── setState(patch) ◀───── イベントハンドラ ◀───────────┘
```

**規則：**

- `state` はモジュールスコープの単一オブジェクト。形は以下

```js
state = {
  scene:    { key, evBase, adjust },
  intent:   'daylightSync',
  subject:  'walking',
  focal:    50,
  camera:   { syncSpeed, maxSS, isoMin, isoMax, isStops },
  lens:     { fMin, fMax },
  flash:    { profileId, modifier, distance, ambientOffset, useHSS, tripod, curtain },
  nd:       [2, 4],              // 装着中の段数
  manual:   { fIndex, ssIndex, isoIndex, locks },   // 計算タブ用
  ui:       { tab, theme, firstRun }
}
```

- **DOM を状態の保管場所にしない。** `element.value` を読んで判断しない。必ず `state` を見る
- `compute()` は純粋関数。`state` だけを引数に取り `derived`（結果・警告・代替案）を返す
- `render()` は `state` と `derived` だけを見る。計算しない
- `setState(patch)` は浅くマージして `compute` → `render` を呼ぶ。**他に再描画経路を作らない**
- 永続化は `setState` の後に `storage.save(state)` を呼ぶ形で1箇所に集約する

## 10. バリデーション

**原則3（入力を拒否しない）。範囲外は弾かずクランプし、何が起きたかを通知する。**

| 項目 | 範囲 | 範囲外の扱い |
| --- | --- | --- |
| 焦点距離 | 8〜1200 mm | クランプ＋トースト「8〜1200mm の範囲に丸めました」 |
| ストロボ距離 | 0.3〜50 m | クランプ＋トースト |
| 出力 Ws | 10〜2000 | クランプ＋トースト |
| 機材係数 k | 2.0〜6.0 | クランプ＋トースト |
| HSS 基準損失 | 1.0〜2.5 段 | クランプ |
| シーン微調整 | ±2.0 段 | スライダーで構造的に範囲外にならない |
| 校正の適正F値 | F1.0〜F32 | クランプ＋トースト |

- 空文字・非数値は**直前の有効値に戻す**（0 にしない。0 は計算を壊す）
- 検証タイミングは `blur` 時。入力中は邪魔しない
- エラーメッセージは**該当フィールドの直下**に出す。画面上部にまとめない
- トーストは 2.5 秒で自動消滅、`role="status"` を付ける

## 11. 初回起動フロー

初期値のままだと実機と合わないが、**急いでいる人を足止めしてはいけない。**

1. 初回のみ「機材セットアップ」を **3ステップ**で表示
   - ステップ1：カメラ（同調速度 / SS上限 / ベースISO / 実用ISO上限）
   - ステップ2：レンズ（開放F値 / 常用焦点距離 / 手ブレ補正段数）
   - ステップ3：ストロボ（出力Ws / HSS対応 / モディファイア）
2. **各ステップに「あとで」ボタンを置く。** 押せば既定値のまま次へ
3. 全スキップも可能。設定タブでいつでも変更できる旨を最後に1行出す
4. 完了後は二度と出さない（`state.ui.firstRun = false`）
5. 設定タブに「セットアップをやり直す」を置く

**未校正のストロボプロファイルには、結果パネルに「推定値」バッジを常時表示する**
（計算仕様 §9 の info 警告と連動）。校正すると消える。これが校正への自然な導線になる。

| 状況 | 文言 |
| --- | --- |
| シーン未選択 | 「シーンを選ぶと計算を始めます」 |

## 13. アクセシビリティ

| 項目 | 要件 |
| --- | --- |
| コントラスト | 本文 4.5:1 以上、大きな数値・アイコン 3:1 以上。**ライト・ダーク両方で実測** |
| フォーカス | フォーカスリングを消さない。`:focus-visible` で 2px の輪郭を出す |
| ラベル | すべての入力に可視ラベル。プレースホルダを唯一のラベルにしない |
| アイコンボタン | `aria-label` 必須 |
| タブ | `role="tablist"` / `role="tab"` / `aria-selected` / 矢印キーで移動 |
| ホイールピッカー | `role="slider"` / `aria-valuenow` / `aria-valuetext`（「F5.6」など人間可読で）/ 矢印キーで 1/3段ずつ移動 |
| 結果パネル | `aria-live="polite"` で値の変化を読み上げる。ただし**連続変更中は抑制**し、確定後に1回だけ |
| 警告 | `role="status"`（info/warn）と `role="alert"`（alert）を使い分ける |
| フォーカス順序 | 視覚順と一致させる。`tabindex` の正数を使わない |
| 色 | 色だけで意味を伝えない。必ずアイコンか文言を併記 |
| 文字サイズ | OS の文字拡大でレイアウトが壊れないこと（`rem` 基準、固定高さを避ける） |

## 14. レスポンシブ

| 条件 | レイアウト |
| --- | --- |
| 320px | 最小保証。横スクロールを発生させない。チップは折り返す |
| 375〜430px | 基準。1カラム＋固定結果パネル |
| **幅 768px 以上 かつ 高さ 600px 以上** | **2カラム。** 左に入力（スクロール）、右に結果パネル（固定・全高）。結果パネルの下部固定を解除する |
| 横向き（縦 500px 未満） | 結果パネルを 120px に圧縮し、EV ルーラーとアンビエント／ストロボの数値のみ残す。警告は折りたたむ |

**2カラムに高さ条件（600px 以上）が必要な理由：**
幅だけで判定すると、横持ちのスマートフォン（例：iPhone 16 Pro Max = 956×440）で
**2カラムと結果パネルの 120px 圧縮が同時に発動し、右カラムが潰れる。**
2カラムは縦に余裕のある画面を前提とした指定なので、高さも条件に含める。

| 画面 | 2カラム | 圧縮 | 結果 |
| --- | --- | --- | --- |
| 956×440（スマホ横持ち） | — | ✓ | 1カラム＋圧縮パネル |
| 768×1024（タブレット縦） | ✓ | — | 2カラム |
| 1280×800（PC） | ✓ | — | 2カラム |
| 440×956（スマホ縦持ち） | — | — | 1カラム＋通常パネル |

`viewport` の `user-scalable=no` を**書かない**（ズームを禁止しない）。
代わりに入力欄を 16px 以上にして自動ズームを防ぐ。

## 15. Service Worker の更新フロー

**自動リロードしない。** 現場で計算中に画面が飛ぶのが最悪の体験。

1. `sw.js` の先頭に `const CACHE = 'expo-v1'` を置く。更新時はここを上げる
2. `install` で全アセットをプリキャッシュ、`activate` で古いキャッシュを削除
3. フェッチ戦略は**キャッシュ優先**（オフライン前提のため）
4. 新しい SW が `waiting` に入ったら、ヘッダーに控えめなバー「新しいバージョンがあります ［更新］」を出す
5. ［更新］を押したときだけ `skipWaiting` → `reload`
6. オフライン時も一切機能を落とさない（そもそもネットワークを使わない）

## 17. 決めていないこと（実機情報が要る項目）

以下は**設定タブの初期値**であり、後から変更できる。分かる範囲で埋めれば精度が上がるが、
**不明なら既定値のまま実装を進めてよい。**

| 項目 | 既定値 | 実機情報があれば |
| --- | --- | --- |
| アプリ名（ホーム画面ラベル） | 「露出アシスト」 | 11文字以内で指定 |
| 同調速度 | 1/250 | カメラ機種による（1/200 の機種も多い） |
| SS 上限 | 1/4000 | 1/8000 の機種なら変更 |
| ベース ISO | 100 | ISO64 の機種がある |
| 実用 ISO 上限 | 6400 | 許容ノイズの好み |
| 手ブレ補正段数 | 0 | ボディ／レンズの公称値の 6〜7割が実用値 |
| レンズ開放F値 | 2.8 | 常用レンズに合わせる |
| ストロボの HSS 対応 | あり | 型番による |
| ストロボの最小発光量 | 1/128 | 1/32 までの機種もある |
| 常用モディファイア | 標準リフレクター | ソフトボックスのサイズなど |
| 機材係数 k | 4.0（未校正） | 校正機能で実測すれば不要 |

**唯一のブロッカーはアプリ名**（`manifest.webmanifest` に必要）。他はすべて既定値で動く。
リポジトリ名は相対パス設計にしてあるため不要。
