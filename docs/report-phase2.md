## 2. ③ 保存形式の判断：**別キー `calMeta`（移行なし）**

```js
profile.cal     = { reflector: 2.33 }                              // 数値のまま
profile.calMeta = { reflector: { model: 'ILCE-7M4', date: '2026:08:03 14:22:10' } }
```

### 理由

| 観点 | `cal` をオブジェクト化（移行あり） | **別キー `calMeta`（採用）** |
| --- | --- | --- |
| 移送の対象 | **実測でしか得られない唯一の資産** | 触らない |
| 得られるもの | キーが1つで済む | — |
| 既存データ | 出所が `null` のオブジェクトになる | 出所が無いまま（**事実に合う**） |
| `schemaVersion` | 上げる | **上げない**（項目の追加。§9） |

**表示用のメタデータのために k の移送を書くのは割に合わない。**
移行コードのバグは「気づかないうちに校正が消える」形で出るので、失敗が表に出にくい。
既存の校正に出所が無いのは事実でもあるので、欠けていても嘘にならない。

### 別キー方式の弱点と手当て

2つのマップが食い違いうる（k を消したのに出所が残る等）。**不変条件を1つ置いた。**

> `calMeta[mod]` は `cal[mod]` があるときだけ意味を持つ。書くときも消すときも対で扱う。

- 書き込み：`runCalibration` が `cal` と `calMeta` を**同じ `updateProfile` 呼び出し**で更新する。
  手入力での再校正では `delete meta[mod]` して古い出所を残さない
- 読み出し：`renderCalHistory` は `cal` を回して `calMeta` を添えるだけ。
  `calMeta` だけ残っていても行は出ない
- 回帰テスト **I7**：`calMeta` を持たない保存データでも `uncalibrated === false` になること

## 3. ② I3 の変異テスト結果

### 数値の訂正（重要）

**ご提示の「変換あり 2.334 / なし 2.268」は、現行の `calibrate()` では再現できませんでした。**
実際の値は次のとおりです（200Ws・3m・ISO100・1/1）。

```
k = N · d / √(S/100) · 2^(p/2) / √Ws

変換あり  F11 → 2^(21/6) = 11.3137085   GN 33.9411   k = 33.9411 / √200 = 2.400000
変換なし  F11 → 11.0                    GN 33.0      k = 33.0    / √200 = 2.333452
差 = 2·log2(2.400000 / 2.333452) = 0.08114段
```

**変換ありの k はちょうど 2.4 になります。** `2^3.5 · 3 / (10·√2) = 3·2^3/10 = 24/10`。
きれいな値なので `near(k, 2.4, 1e-12)` で固定しました。

ご提示の「2.33」は**変換なし**の値（既存テスト #13 の 2.333 と同じ）で、
「2.334 / 2.268」の組は比だけ正しく（1.029 ≈ F11.31/F11.0）、絶対値が Ws 211.5 相当でした。
**方向のご指摘は正しく、変換を入れると k は上がります。**

### 変異テスト

| 変異 | I3 | 判定 |
| --- | --- | --- |
| `calibrateFromLabels` の変換を外す | **落ちる** | 意図どおり |
| `exactFromLabels` の変換を外す | **落ちる**（＋ L7） | 意図どおり |
| `ui.js` が `calibrate()` を直接呼ぶ | **落ちない** | **残る穴。下記** |

### 最初の版には穴がありました

当初 I3 は `exactFromLabels` を直接呼んで比較していました。これだと
**UI 側で変換を書き忘れても落ちません。** そこで変換を `flash.calibrateFromLabels()` に
閉じ込め、I3 は**校正 UI が実際に呼ぶその関数**を通す形に変えました。

残る穴は「UI が `calibrate()` を直接呼ぶように書き換えられた場合」で、これは
`tests.html` からは見えません（ui.js は DOM を要求するため読み込めない）。
関数名で意図が見えるようにし、`flash.js` のコメントと photocal-spec §4.0 に
**「校正 UI から `calibrate()` を直接呼ばないこと」**と明記して代えました。

## 5. 実装で判断したこと

### 入力欄には公称ラベルを入れる

EXIF から読んだ値は `snap(F, …).label`（`11`・`1/250`・`100`）にして入力欄へ入れます。
**厳密値を入力欄に出さない。** 人がカメラの背面液晶と読み合わせる欄なので、
`11.3137` と出ていると「入力が壊れている」ように見えます。
変換は `calibrateFromLabels` に渡す直前の1回だけです。

### 「EXIF」バッジは手で書き換えると消える

`input` イベントでバッジを隠します。**EXIF 由来でない値に EXIF と表示しない**ためです。

### 非発光は実行前に止める

`calibrationNotes` の `alert` が1件でもあれば `runCalibration` は例外を投げて中断します
（warn は通す）。発光していない写真で校正すると k が丸ごと狂うので、警告だけでは足りません。

### F値の食い違いは「F8.0」と表示される

系列のラベルをそのまま使うためです（`F_LABELS[18] === '8.0'`）。
仕様の文言は「F8」でしたが、アプリの他の表示（ダイアル・等価露出一覧）と揃えました。

## 7. あとから見つけた不具合（未修正）

### 7.1 手入力と EXIF の食い違いが**画面に出ない**

仕様 §4.3 が「3つ目が実用上いちばん効く。転記ミスをその場で気づける」と書いている検証が、
**実装では計算されたあと捨てられている。**

```js
// js/ui.js runCalibration()
const blocking = exif
  ? calibrationNotes(exif, { …, inputF: fAperture })
      .filter((n) => n.level === 'alert')   // ← warn（食い違い）はここで落ちる
  : [];
if (blocking.length) throw new Error(blocking[0].text);
```

- **校正の実行時：** 食い違いは `warn` なので `blocking` に残らず、どこにも表示されない
- **写真の読み取り時：** `inputF: null` を渡しているので、そもそも判定していない
  （読み取った直後は入力欄を EXIF で上書きした後なので、その時点では必ず一致する）

**`calibrationNotes` 自体は正しく、テスト I6 も通っている。** 抜けているのは UI への配線だけ。
純粋関数のテストは通るのに機能が届いていない、という形なので、
**I6 が緑であることを根拠に「実装済み」と判断しないこと。**

直すなら、`runCalibration` で `warn` を捨てずに `notes` 欄へ出す（実行は止めない）。
Q9 はこの不具合を踏む手順なので、修正後に**同じ手順で**確認できる。

### 7.2 校正値を消す UI は無い

| UI | 対象 | `cal` と `calMeta` の同期 |
| --- | --- | --- |
| 「初期値に戻す」（設定タブ末尾） | **全設定** | `setState(clone(defaultState))` で丸ごと置換。両方 `{}` に戻るので**対で消える** |
| 「校正を取り消す」（スマホ露出計） | `state.phone` のみ | ストロボの `cal` / `calMeta` には触れない |

**モディファイア単位でストロボ校正を消す UI は存在しない。**
したがって「`cal` を消したのに `calMeta` が残る」経路は、いまのところ再校正（Q19）だけ。
そこは `runCalibration` が `delete meta[mod]` で対処している。

削除 UI を足すときは、**`cal[mod]` と `calMeta[mod]` を同じ `updateProfile` 呼び出しで消すこと**
（`docs/MAINTENANCE.md` §9 の不変条件）。
